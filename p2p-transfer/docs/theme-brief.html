Oxfer theme brief

Live lab: designers should use /theme.html (color pickers, preview, JSON/zip export). This page is the static spec behind it.

Hand this to a designer proposing a new in-app theme. A theme is a named palette (like today’s Clean and Rusty) with a light and dark mode. Clean is the default.

What to return: a theme name, the 13 tokens below filled in for both light and dark, a corner-radius choice, browser chrome colors, and one mock of the home screen plus one of the send/receive header. Keep token names — the app maps UI to these slots, not to raw hex.

Product

  • Oxfer — peer-to-peer file transfer. No cloud. Browser and desktop, same UI.
  • Rendered in egui (immediate-mode), not CSS. Themes are color + radius tokens, not stylesheets.
  • Users pick a theme (Clean / Rusty / proposed) and independently toggle light/dark.
  • Live app: oxfer.app

Default theme — Clean

Cool blue-gray “file messenger”. Surfaces step from page background up to raised chips. Primary is the action blue; secondary is a lighter/darker sibling used for accents, copied-state, and status pills.

Derived (do not invent new slots — specify if you want different alphas)

  • Selection fill = primary at 24% opacity (60/255).
  • Accent pill fill = secondary at 7% opacity (18/255).
  • Active widget stroke = primary; hover stroke = outline; idle stroke = outline_var.

Logo and chrome (mostly outside the theme)

  • Wordmark is a black/white SVG pair, not recolored per theme. Light mode uses the black cut, dark mode the white cut.
  • Favicon OX sits on surface with on_surface letters (Clean values today).
  • Browser theme-color / body = header surface and page bg.
  • Loading spinner = dark primary #50a2e9; loading label = light primary #2077c1. A new theme should name replacements.
